About BYOD Synthetic Data Generator

Made-up data with the same structure as your file

🛡️ What happens to your data

Your file is sent to this server and analysed there. It does not stay in your browser. Rows are not sent to the AI model. The model receives a description of the file: column names, data types, counts and summary statistics.

For text columns the model receives lengths and formats, plus the labels of repeated categories (such as M / F) in Balanced and Permissive modes. In Strict mode it receives no text values. Other text values, such as IDs, emails, phone numbers and free text, are replaced with placeholders. Column names are always sent as they are.

For number columns, the real smallest and largest values are sent in Balanced and Permissive modes, unless the column has fewer than 20 values or a name that looks like an identifier. For date columns, the range is widened to whole months or years.

Do not upload real study data or patient identifiers. This release has not been approved for them. No compliance assessment has been done.

This site has no sign-in. Anyone who can reach it on the organisation network (VPN) can use it.

More detail: what the AI model receives The model is an Azure OpenAI model hosted by the organisation. It receives:
  • Column names: always, exactly as they are in the file.
  • For every column: the data type and the number of values, empty values and distinct values.
  • Number columns: the average, the spread and similar summary numbers. In Balanced and Permissive modes, for a column with 20 or more values, this includes the real smallest, largest, middle and quartile values. In Strict mode, and for a column with fewer than 20 values, the numbers are rounded and the range is widened. A column whose name looks like an identifier (for example patient_id, mrn or zip) sends no smallest, largest, middle or quartile value.
  • Date columns: the range, widened to whole months. It is widened to whole years for a column named like a date of birth, in Strict mode, and for a column with fewer than 20 values. The exact earliest and latest dates are not sent. The most common hour and weekday are sent.
  • Text columns: lengths, whether the values look like emails, web addresses, phone numbers or dates, and how often the most common values occur. The values themselves are replaced with placeholders such as value_0, with one exception. A value is sent as it is when it is a short label (30 characters or fewer) that occurs at least 5 times, in a column with 20 or more values, few distinct values (up to 10 in Balanced mode, up to 50 in Permissive mode), a name that does not look like an identifier, and no value that looks like an email, phone number, date or long number. Strict mode sends no text value.
  • This rule cannot tell a category from a name. A person's name that occurs 5 or more times in a column with an ordinary name is treated as a category label and is sent in Balanced and Permissive modes.
  • Shared beginnings and endings: outside Strict mode, for a column with 20 or more values, a beginning or ending of up to 6 characters with no digits that many values share (for example the letters in front of an ID number) can be sent.
  • ID-shaped columns: the shape, for example "MRN-<7 digits>". A real ID is never given as an example.
  • Relationships: how strongly columns move together.
  • A data dictionary, if you upload one: its column names, types, descriptions, allowed values, ranges and patterns, cut to a size limit.
, what is stored on the server
  • The description sent to the model and the Python script the model wrote are saved in a cache on the server's disk, so a later request with similar data can reuse the script. They stay there until the cache is cleared. A request sent with use_cache set to false does not read or write the cache.
  • Column names from cached descriptions are listed on the Usage Dashboard, which every user of this site can open.
  • The uploaded file is not written to the cache. While a request is being processed the file is held in memory, and the web framework may also keep it in a temporary file on disk.
  • An uploaded data dictionary, and a preview made from one, are kept in the server's memory for up to 30 minutes after their last use.
  • A usage log records the time, the number of rows and columns, and how long each step took.
 and how the script is run The script the model writes is checked before it runs. It may use only data libraries and is refused if it asks for files, the network or other processes. It then runs as a separate process, with a time limit, on the same server as this application. This is a check, not full isolation. If the AI model is not available, generation stops with an error message. There is no other generator behind it. .

📊 Two Ways to Generate Data

1. From a data file: Upload your data file Supported formats: CSV, JSON, Excel (.xlsx, .xls), Parquet, TSV. The format is taken from the file name. Files are read with pandas The server loads the file into a pandas table to:
  • Detect data types
  • Calculate statistics
  • Describe patterns and relationships between columns
The whole file is read into memory. An upload can be at most 50 MB unless the server was configured with a different limit. . . The server builds a description of it and the AI model writes a script that makes similar, made-up data.
2. From a data dictionary: Define your structure with a data dictionary Upload a dictionary file (JSON, YAML, CSV, Excel, PDF) that defines:
  • Column names and types
  • Constraints (min/max values, allowed values)
  • Required vs optional fields
  • Format patterns
{ "columns": { "patient_id": { "type": "integer", "constraints": {"min_value": 1000, "max_value": 9999} }, "treatment_date": {"type": "datetime"}, "medication": { "type": "string", "constraints": {"allowed_values": ["Aspirin", "Metformin"]} } } }
No data file is needed. The content of the dictionary is sent to the AI model. without a data file.
Both together: Upload a data file and a dictionary for dictionary constraints When you provide both:
  1. The description is built from your data file
  2. The dictionary constraints are added to it
  3. The AI model is told that the dictionary constraints take priority
Example: your data shows ages 18-95, but the dictionary specifies max_value: 65. The model is told to keep ages at or below 65. .

🔬 Advanced Features

The system includes domain detection The server recognises:
  • Date columns: Fields with 'date', 'time', 'created', 'updated' in the name are generated as dates
  • Medical columns: Medication, lab test and diagnosis columns are matched to the clinical reference library
  • Email/Phone: The format is detected and described to the model
  • IDs: Described by shape (letters, then a number of digits)
, a clinical reference library A built-in list, not taken from any uploaded file, of:
  • About 70 common medications (Metformin, Lisinopril, etc.)
  • About 60 lab tests (CBC, Glucose, Hemoglobin A1c)
  • About 50 diagnoses (Hypertension, Diabetes, etc.)
  • Medical units (mg, mL, mg/dL, mmol/L)
When a medical column is detected, values from this list are suggested to the model. for healthcare data, and a script cache The Python script written by the AI model is saved on the server's disk together with the description it was written for. A later request with a similar description and the same number of rows reuses the script, which avoids a call to the AI model. .

🚀 Use it from code

Your own programs can generate data too. Copy a block below, paste it, and change only the file names. Replace https://YOUR-SITE with the address of this site (the page fills it in for you when JavaScript is on).

API key: the X-API-Key header is only needed if this server was configured with a key; if it was not, the header is ignored. The examples read the key from the environment variable MOCKDATA_API_KEY. It applies to the /api/v1 routes only.

Generation calls an AI model, so a request can take a minute or more.

Generate from a JSON request

curl · POST /api/v1/generate 
curl -X POST "https://YOUR-SITE/api/v1/generate" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $MOCKDATA_API_KEY" \
  -d '{"csv_text": "widget_id,colour,weight_g\nW001,red,12.5\nW002,blue,14.1\nW003,green,11.8\n", "num_rows": 20}'
Python (requests) · POST /api/v1/generate 
import os

import requests

BASE = "https://YOUR-SITE"
# Only needed if the server was configured with a key; ignored otherwise.
HEADERS = {"X-API-Key": os.environ.get("MOCKDATA_API_KEY", "")}

response = requests.post(
    BASE + "/api/v1/generate",
    headers=HEADERS,
    json={
        "csv_text": "widget_id,colour,weight_g\nW001,red,12.5\nW002,blue,14.1\nW003,green,11.8\n",
        "num_rows": 20,
    },
    timeout=300,  # generation calls an AI model and can take a minute or more
)
body = response.json()
if not response.ok:
    raise SystemExit(f"{body['error_class']}: {body['error']}")

print(body["shape"], body["columns"])
for row in body["data"][:5]:
    print(row)
JavaScript (fetch, Node 18+) · POST /api/v1/generate 
const BASE = "https://YOUR-SITE";
// Only needed if the server was configured with a key; ignored otherwise.
const API_KEY = (typeof process !== "undefined" && process.env.MOCKDATA_API_KEY) || "";

async function generate() {
  const response = await fetch(BASE + "/api/v1/generate", {
    method: "POST",
    headers: { "Content-Type": "application/json", "X-API-Key": API_KEY },
    body: JSON.stringify({
      csv_text: "widget_id,colour,weight_g\nW001,red,12.5\nW002,blue,14.1\nW003,green,11.8\n",
      num_rows: 20,
    }),
  });
  const body = await response.json();
  if (!response.ok) {
    throw new Error(body.error_class + ": " + body.error);
  }
  return body.data; // one object per row
}

generate().then(console.table).catch(console.error);

Send a file from disk

Python · local CSV in, pandas DataFrame out 
import os
from pathlib import Path

import pandas as pd
import requests

BASE = "https://YOUR-SITE"
SOURCE_FILE = "your_data.csv"
# Only needed if the server was configured with a key; ignored otherwise.
HEADERS = {"X-API-Key": os.environ.get("MOCKDATA_API_KEY", "")}

response = requests.post(
    BASE + "/api/v1/generate",
    headers=HEADERS,
    json={
        "csv_text": Path(SOURCE_FILE).read_text(encoding="utf-8"),
        "num_rows": 500,
    },
    timeout=300,  # generation calls an AI model and can take a minute or more
)
body = response.json()
if not response.ok:
    raise SystemExit(f"{body['error_class']}: {body['error']}")

df = pd.DataFrame(body["data"], columns=body["columns"])
print(df.head())
df.to_csv("synthetic.csv", index=False)
curl · upload a file, save a CSV · POST /generate 
curl -X POST "https://YOUR-SITE/generate" \
  -F "file=@your_data.csv" \
  -F "num_rows=1000" \
  -F "output_format=csv" \
  -o synthetic.csv

The upload accepts CSV, TSV, JSON, Excel and Parquet files. Leave out num_rows to get as many rows as the source file. output_format can be csv, json or excel. If the request fails, synthetic.csv will hold a short JSON error message instead of data.

Generate from a data dictionary only

curl · no data file needed · POST /generate-with-dictionary 
curl -X POST "https://YOUR-SITE/generate-with-dictionary" \
  -F "dictionary_file=@dictionary.json" \
  -F "num_rows=1000" \
  -F "output_format=csv" \
  -o synthetic.csv

Add -F "data_file=@your_data.csv" to also use a real file for the statistics. num_rows defaults to 100 on this route. If the dictionary describes several tables, name one with -F "table=TABLE_NAME".

Request fields: POST /api/v1/generate

Send a JSON object. Give exactly one of csv_text or data_content. Unknown fields are rejected.

FieldTypeDefaultMeaning
csv_textstringnoneThe source data as plain CSV text, header row first.
data_contentstring (base64)noneThe source file's bytes, base64-encoded. Use together with format.
formatcsv, tsv, json, excel or parquetcsvFormat of data_content. Ignored for csv_text.
num_rowswhole number, 1 to 100,000source row countRows to generate. Leave out to match the source.
match_thresholdnumber, 0 to 10.8How closely the statistics must match the source.
safety_modestrict, balanced or permissivebalancedHow much of the text values the AI model may see. Strict sends none.
use_cachetrue or falsetrueReuse a cached generation script for similar data.
modeltext, optionalserver defaultName of an allowed AI model. See GET /api/models. A name not on the list is refused.

Response (200): a JSON object with status (always "success"), data (one object per row), shape ([rows, columns]), columns (column names in order) and generation_info (how the data was made).

Limits and errors

Limits: num_rows is at most 100,000. A request body to /api/v1 may be at most 10 MB unless the server was configured with a different limit (MOCKDATA_API_MAX_BYTES).

Errors: every failure under /api/v1 has the same shape. The older upload routes (/generate, /generate-with-dictionary) mostly answer with {"detail": "..."} instead.

The one error shape of /api/v1 
{"status": "error", "error": "what went wrong, in words", "error_class": "RequestValidationError"}

For AI agents: A2A and MCP

A2A: this site publishes an agent card at /.well-known/agent.json and accepts agent messages at POST /a2a/mock-data-generator. The body is this project's own JSON envelope (not a general A2A standard message) with a payload (the file as base64 in data_content, plus options) and a metadata object (correlation_id, cycle, agent_id).

curl · read the agent card · GET /.well-known/agent.json 
curl "https://YOUR-SITE/.well-known/agent.json"

MCP: the MCP server is not reachable at this site's address. It is a program you start on your own machine from a copy of the source code (it talks over standard input and output), and it offers two tools: generate_synthetic_data and extract_metadata.

shell · start the MCP server (run in the source code folder) 
python -m src.mcp_server

Local development note: when you run the app on your own machine, the address is usually http://localhost:8201.

Generate data in multiple formats Output formats supported:
  • CSV: Standard comma-separated values
  • JSON: Array of objects, one per row
  • Excel: One .xlsx file
Asking for more than one file returns a ZIP archive. and integrate with your CI/CD pipelines For example:

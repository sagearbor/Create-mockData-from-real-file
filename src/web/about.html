About BYOD Synthetic Data Generator

Privacy-First Synthetic Data Generation

🛡️ How We Protect Your Data

Your data is processed locally Data files are loaded into memory on the server, never saved to disk. The files exist only during processing and are immediately garbage collected after use. No permanent storage occurs. and only statistical metadata We extract only aggregate statistics like mean, min, max, standard deviation, and data types. No actual data values are sent to the AI. For example, from patient names we only extract "string column, average length 15 characters, 95% unique values" - never the actual names. is sent to the AI model. The LLM NEVER sees your actual data The Azure OpenAI model receives only:

  • Column names and types
  • Statistical distributions
  • Correlations between columns
  • Pattern descriptions
It generates Python code based on these statistics, which then runs locally to create synthetic data. .

📊 Two Ways to Generate Data

1. From Real Data: Upload your data file Supported formats: CSV, JSON, Excel (.xlsx, .xls), Parquet, TSV. The system automatically detects the format and extracts the structure. Files are processed using pandas We use pandas DataFrames to analyze your data efficiently. This allows us to:

  • Handle large files (though streaming for 1GB+ files is planned)
  • Detect data types automatically
  • Calculate statistics in a single pass
  • Identify patterns and correlations
for maximum compatibility. to extract patterns and generate similar synthetic data.

2. From Data Dictionary: Define your structure with a data dictionary Upload a dictionary file (JSON, YAML, CSV, Excel, PDF) that defines:

  • Column names and types
  • Constraints (min/max values, allowed values)
  • Required vs optional fields
  • Format patterns
{ "columns": { "patient_id": { "type": "integer", "constraints": {"min_value": 1000, "max_value": 9999} }, "treatment_date": {"type": "datetime"}, "medication": { "type": "string", "constraints": {"allowed_values": ["Aspirin", "Metformin"]} } } }
No real data file needed - generates purely from specifications! without needing any real data.

Bonus: Combine both approaches by uploading data AND a dictionary for constraint enforcement When you provide both:

  1. Statistical patterns are extracted from your real data
  2. Dictionary constraints override these statistics
  3. Result: Realistic patterns with enforced business rules
Example: Your data shows ages 18-95, but dictionary specifies max_value: 65. Generated data will follow the distribution pattern but cap at 65. .

The system includes domain detection Automatically recognizes:

  • Date columns: Fields with 'date', 'time', 'created', 'updated' generate proper dates
  • Medical data: Medication names, lab tests, diagnoses use clinical reference library
  • Email/Phone: Patterns detected and appropriate formats generated
  • IDs: Sequential or UUID patterns maintained

When medical columns are detected, realistic clinical values are used instead of random strings. for healthcare data, and smart caching The system caches: Generation scripts Python code generated by the LLM is cached with metadata signatures. 🚀 Use it from code

Your own programs can generate data too. Copy a block below, paste it, and change only the file names. Replace https://YOUR-SITE with the address of this site (the page fills it in for you when JavaScript is on).

API key: the X-API-Key header is only needed if this server was configured with a key; if it was not, the header is ignored. The examples read the key from the environment variable MOCKDATA_API_KEY. It applies to the /api/v1 routes only.

Generation calls an AI model, so a request can take a minute or more.

Generate from a JSON request

curl · POST /api/v1/generate 
curl -X POST "https://YOUR-SITE/api/v1/generate" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $MOCKDATA_API_KEY" \
  -d '{"csv_text": "widget_id,colour,weight_g\nW001,red,12.5\nW002,blue,14.1\nW003,green,11.8\n", "num_rows": 20}'
Python (requests) · POST /api/v1/generate 
import os

import requests

BASE = "https://YOUR-SITE"
# Only needed if the server was configured with a key; ignored otherwise.
HEADERS = {"X-API-Key": os.environ.get("MOCKDATA_API_KEY", "")}

response = requests.post(
    BASE + "/api/v1/generate",
    headers=HEADERS,
    json={
        "csv_text": "widget_id,colour,weight_g\nW001,red,12.5\nW002,blue,14.1\nW003,green,11.8\n",
        "num_rows": 20,
    },
    timeout=300,  # generation calls an AI model and can take a minute or more
)
body = response.json()
if not response.ok:
    raise SystemExit(f"{body['error_class']}: {body['error']}")

print(body["shape"], body["columns"])
for row in body["data"][:5]:
    print(row)
JavaScript (fetch, Node 18+) · POST /api/v1/generate 
const BASE = "https://YOUR-SITE";
// Only needed if the server was configured with a key; ignored otherwise.
const API_KEY = (typeof process !== "undefined" && process.env.MOCKDATA_API_KEY) || "";

async function generate() {
  const response = await fetch(BASE + "/api/v1/generate", {
    method: "POST",
    headers: { "Content-Type": "application/json", "X-API-Key": API_KEY },
    body: JSON.stringify({
      csv_text: "widget_id,colour,weight_g\nW001,red,12.5\nW002,blue,14.1\nW003,green,11.8\n",
      num_rows: 20,
    }),
  });
  const body = await response.json();
  if (!response.ok) {
    throw new Error(body.error_class + ": " + body.error);
  }
  return body.data; // one object per row
}

generate().then(console.table).catch(console.error);

Send a file from disk

Python · local CSV in, pandas DataFrame out 
import os
from pathlib import Path

import pandas as pd
import requests

BASE = "https://YOUR-SITE"
SOURCE_FILE = "your_data.csv"
# Only needed if the server was configured with a key; ignored otherwise.
HEADERS = {"X-API-Key": os.environ.get("MOCKDATA_API_KEY", "")}

response = requests.post(
    BASE + "/api/v1/generate",
    headers=HEADERS,
    json={
        "csv_text": Path(SOURCE_FILE).read_text(encoding="utf-8"),
        "num_rows": 500,
    },
    timeout=300,  # generation calls an AI model and can take a minute or more
)
body = response.json()
if not response.ok:
    raise SystemExit(f"{body['error_class']}: {body['error']}")

df = pd.DataFrame(body["data"], columns=body["columns"])
print(df.head())
df.to_csv("synthetic.csv", index=False)
curl · upload a file, save a CSV · POST /generate 
curl -X POST "https://YOUR-SITE/generate" \
  -F "file=@your_data.csv" \
  -F "num_rows=1000" \
  -F "output_format=csv" \
  -o synthetic.csv

The upload accepts CSV, TSV, JSON, Excel and Parquet files. Leave out num_rows to get as many rows as the source file. output_format can be csv, json or excel. If the request fails, synthetic.csv will hold a short JSON error message instead of data.

Generate from a data dictionary only

curl · no data file needed · POST /generate-with-dictionary 
curl -X POST "https://YOUR-SITE/generate-with-dictionary" \
  -F "dictionary_file=@dictionary.json" \
  -F "num_rows=1000" \
  -F "output_format=csv" \
  -o synthetic.csv

Add -F "data_file=@your_data.csv" to also use a real file for the statistics. num_rows defaults to 100 on this route. If the dictionary describes several tables, name one with -F "table=TABLE_NAME".

Request fields: POST /api/v1/generate

Send a JSON object. Give exactly one of csv_text or data_content. Unknown fields are rejected.

FieldTypeDefaultMeaning
csv_textstringnoneThe source data as plain CSV text, header row first.
data_contentstring (base64)noneThe source file's bytes, base64-encoded. Use together with format.
formatcsv, tsv, json, excel or parquetcsvFormat of data_content. Ignored for csv_text.
num_rowswhole number, 1 to 100,000source row countRows to generate. Leave out to match the source.
match_thresholdnumber, 0 to 10.8How closely the statistics must match the source.
safety_modestrict, balanced or permissivebalancedPrivacy level for categorical values.
use_cachetrue or falsetrueReuse a cached generation script for similar data.

Response (200): a JSON object with status (always "success"), data (one object per row), shape ([rows, columns]), columns (column names in order) and generation_info (how the data was made).

Limits and errors

Limits: num_rows is at most 100,000. A request body to /api/v1 may be at most 10 MB unless the server was configured with a different limit (MOCKDATA_API_MAX_BYTES).

Errors: every failure under /api/v1 has the same shape. The older upload routes (/generate, /generate-with-dictionary) mostly answer with {"detail": "..."} instead.

The one error shape of /api/v1 
{"status": "error", "error": "what went wrong, in words", "error_class": "RequestValidationError"}
HTTP statuserror_classWhat it means
400GenerationErrorThe source data could not be read or used.
401InvalidApiKeyThe server requires a key and X-API-Key is missing or wrong.
413RequestTooLargeThe request body is over the size limit.
422RequestValidationErrorA field is missing, unknown or out of range.
500InternalErrorUnexpected server error. No data was generated.
502variesThe AI generation failed. No data was generated.
503variesAI is not configured on the server. No data was generated.

For AI agents: A2A and MCP

A2A: this site publishes an agent card at /.well-known/agent.json and accepts agent messages at POST /a2a/mock-data-generator. The body is this project's own JSON envelope (not a general A2A standard message) with a payload (the file as base64 in data_content, plus options) and a metadata object (correlation_id, cycle, agent_id).

curl · read the agent card · GET /.well-known/agent.json 
curl "https://YOUR-SITE/.well-known/agent.json"

MCP: the MCP server is not reachable at this site's address. It is a program you start on your own machine from a copy of the source code (it talks over standard input and output), and it offers two tools: generate_synthetic_data and extract_metadata.

shell · start the MCP server (run in the source code folder) 
python -m src.mcp_server

Local development note: when you run the app on your own machine, the address is usually http://localhost:8201.
